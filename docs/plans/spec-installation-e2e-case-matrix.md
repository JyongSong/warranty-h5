## 목적

고객에게 설치 주소 입력 안내가 발송된 주문 1건을 기준으로, 고객 입력부터 기사 후보 생성, 관리자 기사 배정, 기사 응답, 관리자 설치 완료까지 이어지는 설치 주문 흐름이 정상 동작하는지 확인한다.

이 문서는 사람이 읽고 현재 커버리지를 판단할 수 있도록, 각 케이스의 검증 방식과 결과를 정리한다.

## 검증 방식

검증은 세 가지 방식으로 나누어 수행했다.

| 방식 | 설명 |
| --- | --- |
| 실제 화면 확인 | 인앱 브라우저에서 고객/기사/백오피스 화면을 열어 표시 상태와 주요 버튼을 확인 |
| 서버 액션/도메인 테스트 | UI 클릭과 동일한 서버 액션 또는 도메인 함수 단위로 상태 전이와 DB 변경 조건을 검증 |
| 자동화 테스트 | Vitest로 정상 흐름과 예외 흐름을 반복 가능한 테스트로 검증 |

모든 예외 케이스를 운영 주문 데이터로 직접 변형해 클릭하지는 않았다. 운영 주문을 불필요하게 오염시키지 않기 위해, 예외 흐름은 대부분 자동화 테스트와 서버 액션 기준으로 검증했다.

## UI 다이얼로그 변경 사항

기존 백오피스 상세 화면의 관리자 작업 중 일부는 `window.prompt`, `window.confirm`, `window.alert`에 의존했다. 인앱 브라우저에서는 이 API들이 지원되지 않아 실제 클릭 검증이 막혔다.

현재는 다음 작업을 UI 다이얼로그로 대체했다.

| 작업 | 현재 방식 |
| --- | --- |
| 기사 직접 지정 | `AdminActionDialog`에서 기사 ID와 사유 입력 |
| 수동 처리 전환 | `AdminActionDialog`에서 사유 입력 |
| 기사 후보 다시 찾기 | `AdminActionDialog`에서 사유 입력 |
| 후보 승인 | `AdminActionDialog`로 확인 |
| 설치 완료 | `AdminActionDialog`에서 완료 사유 입력 |
| 주문 취소 | `AdminActionDialog`에서 취소 사유 입력 |
| 예외 해결 | `AdminActionDialog`에서 해결 사유 입력 |
| 배정 승인 목록 | `AssignmentApproveDialog`로 확인 |

따라서 prompt/confirm/alert 때문에 막히던 관리자 작업은 현재 Open Defect가 아니다.
