# 설치 배정 기능 목록

> 목적: 설치 주문 수집부터 고객 입력, 설치 기사 배정 요청, 기사 응답, 예외 처리, 완료 처리까지의 기능 책임을 정의한다.
> 원칙: 시스템이 자동으로 배정 요청을 진행하고, 관리자는 예외와 수동 보정에 집중한다.

## 1. 운영 원칙

1-1. 시스템은 설치 주문 1건을 설치 예약 1건으로 생성한다.
1-2. 시스템은 고객 입력을 받은 뒤 자동으로 설치 기사 후보를 선정한다.
1-3. 시스템은 자동 요청 조건을 충족하면 1순위 후보에게 배정 요청을 발송한다.
1-4. 관리자는 모든 후보를 사전 승인하지 않고, 예외와 수동 처리 대상만 확인한다.
1-5. 자동 배정 요청을 받은 설치 기사가 거절하거나 응답하지 않으면 시스템은 차순위 후보에게 자동으로 요청한다.
1-6. 자동 처리 한도에 도달하거나 후보가 없으면 관리자가 수동으로 처리한다.
1-7. 상태와 화면은 현재 해야 할 다음 액션이 누구에게 있는지를 기준으로 설계한다.

## 2. 사용자와 책임

2-1. 고객은 설치 희망 날짜, 설치 방문 주소, 연락처를 입력하고 메모를 선택으로 입력할 수 있다.
2-2. 시스템은 주문 수집, 고객 링크 발송, 후보 선정, 기사 요청, 차순위 진행, SMS 발송, 예외 생성을 수행한다.
2-3. 설치 기사는 배정 요청을 수락하거나 거절한다.
2-4. 관리자는 예외 보드에서 수동 처리 필요 건을 확인하고 직접 기사 지정, 재시도, 취소, 완료 처리를 수행한다.
2-5. 관리자는 자동 배정이 정상 진행 중인 건에 대해 기본적으로 승인 액션을 하지 않는다.

## 3. 핵심 기능

3-1. 설치 주문 수집과 설치 예약 생성
3-2. 고객 설치 정보 입력 링크 발송
3-3. 고객 입력 검증과 제출 완료 처리
3-4. 고객 입력 검증 실패 오류 표시
3-5. 설치 희망 날짜 범위 검증
3-6. 고객 미입력 리마인드
3-7. 고객 미입력 기한 초과 시 주문 배송지 폴백과 자동 배정 전환
3-8. 제품 기반 설치 요구 능력 산정
3-9. 주소 기반 서비스 지역 표준화
3-10. 설치 기사 후보 자동 선정
3-11. 1순위 설치 기사 배정 요청 자동 발송
3-12. 설치 기사 수락/거절 응답 처리
3-13. 설치 기사 무응답 timeout 처리
3-14. 차순위 설치 기사 자동 요청
3-15. 배정 요청 SMS 재시도 대기 처리
3-16. 후보 없음, 후보 소진, SMS 실패, 일정 임박 예외 생성
3-17. 관리자 예외 보드와 설치건 상세
3-18. 관리자 직접 기사 지정
3-19. 관리자 재시도 실행
3-20. 설치건 취소
3-21. 설치 완료 확정
3-22. SMS 발송 로그와 감사 이력
3-23. 동시 실행과 중복 배정 요청 방지

## 4. 기본 사용자 흐름

4-1. 시스템이 신규 설치 주문을 수집한다.
4-2. 시스템이 설치 예약을 생성하고 고객에게 입력 링크를 보낸다.
4-3. 고객이 설치 희망 날짜, 방문 주소, 연락처를 제출한다.
4-4. 시스템이 설치 요구 능력과 지역 key를 산정한다.
4-5. 시스템이 1순위 설치 기사 후보를 선정하고 관리자 검토 대기로 전환한다.
4-6. 관리자가 후보를 승인하면 시스템이 배정 요청 SMS를 발송한다.
4-7. SMS 발송 또는 도달 확인이 일시 실패하면 시스템은 같은 업무 대상 기준으로 SMS 재시도를 대기한다.
4-8. 설치 기사가 수락하면 시스템은 배정 완료 SMS를 고객에게 보내고 설치 기사에게 해피콜 안내 SMS를 보낸다.
4-9. 자동 배정 요청을 받은 설치 기사가 거절하거나 timeout되면 시스템은 차순위 후보를 선정하고 관리자 검토 대기로 전환한다.
4-10. 자동 진행이 불가능하면 시스템은 예외를 만들고 관리자가 처리한다.

## 5. 관리자 기능

5-1. 관리자는 예외 보드에서 수동 처리 필요 건을 우선순위대로 확인한다.
5-2. 관리자는 설치건 상세에서 주문, 고객 입력, 후보 선정 근거, 요청 이력, SMS 이력, 예외 이력을 확인한다.
5-3. 관리자는 수동 처리 필요 건에 직접 설치 기사를 지정할 수 있다.
5-4. 관리자는 SMS 실패 건의 재발송을 실행할 수 있다.
5-5. 관리자는 자동 진행 중인 건을 필요하면 수동 처리로 전환할 수 있다.
5-6. 시스템은 관리자 수동 처리 전환 시 활성 자동 배정 시도를 `ADMIN_MANUAL_OVERRIDDEN`으로 종료하고 관리자 ID, 전환 시각, 수동 전환 사유를 기록한다.
5-7. 관리자는 취소 정책이 허용하는 설치건을 취소할 수 있고, 현재 상태와 관계없이 설치 완료 확정을 수행할 수 있다.
5-8. 관리자 직접 지정은 비활성 설치 기사, 필수 설치 능력 미충족 설치 기사, Aqara App 요구 등급 미충족 설치 기사를 허용하지 않는다.
5-9. 관리자가 지역 매칭 기준을 충족하지 못하는 설치 기사를 지정하려면 수동 지정 사유를 기록해야 한다.

## 6. 설치 기사 기능

6-1. 설치 기사는 SMS 링크로 배정 요청 상세에 접근한다.
6-2. 설치 기사는 수락 전 고객 전체 이름, 전화번호, 상세 주소를 보지 않는다.
6-3. 설치 기사는 설치 희망 날짜, 대략 지역, 제품 요약, 필수 능력을 보고 수락 또는 거절한다.
6-4. 설치 기사가 수락하면 고객 연락처와 상세 주소를 확인할 수 있다.
6-5. 설치 기사가 자동 배정 요청을 거절하면 시스템은 거절 사유를 기록하고 차순위 요청을 진행한다.
6-6. 설치 기사가 관리자 직접 지정 요청을 거절하면 시스템은 차순위 자동 요청을 진행하지 않고 수동 처리로 되돌린다.
6-7. 설치 기사가 배정 요청 SMS 발송 성공 후 24시간 안에 응답하지 않으면 시스템은 timeout으로 처리한다.

## 7. 예외 기능

7-1. 후보 없음 예외: 필터링 결과 배정 가능한 설치 기사가 없는 경우.
7-2. 후보 소진 예외: 자동 재시도 한도 안에서 모든 후보가 실패한 경우.
7-3. 고객 정보 부족 예외: 고객 입력과 주문 배송지 폴백으로도 후보 선정 정보가 부족한 경우.
7-4. SMS 실패 예외: 필수 SMS가 재시도 후에도 발송되지 않거나 도달하지 않은 경우.
7-5. 일정 임박 예외: 설치 희망 날짜 하루 전 09:00 KST까지 기사 수락이 완료되지 않은 경우.
7-6. 예외는 현재 미해결 상태와 과거 해결 이력을 구분한다.
7-7. 비배정 SMS 최종 실패는 업무 상태를 되돌리지 않고 SMS 실패 예외로 관리한다.

## 8. 취소 정책

8-1. 관리자는 설치 완료 또는 이미 취소된 설치건이 아닌 경우 설치건을 취소할 수 있다.
8-2. 설치건 취소 시 시스템은 고객과 설치 기사에게 자동 SMS를 발송하지 않는다.
8-3. 설치 기사 배정 수락 완료 후 설치건을 취소해도 이미 확정된 배정 카운트는 유지한다.

## 9. 완료 정책

9-1. 관리자는 슈퍼 권한을 가지며 설치건의 현재 상태와 관계없이 설치 완료를 확정할 수 있다.
9-2. 설치 완료 확정 시 시스템은 활성 배정 시도가 있으면 `ADMIN_COMPLETED`로 종료하고 완료 처리 관리자 ID, 완료 시각, 완료 사유를 기록한다.
9-3. 설치 완료 후 설치 예약은 `COMPLETED` 상태가 된다.

## 10. 제외 범위

10-1. 여러 설치 주문을 묶는 통합 배정은 제외한다.
10-2. 지도 API 기반 거리 계산과 이동 비용 산정은 제외한다.
10-3. 설치 기사 시간표 충돌 판단은 제외한다.
10-4. 설치 기사 평점 기반 우선순위는 제외한다.
10-5. 설치 기사 프로필 관리 UI는 제외한다.
10-6. 제품-설치 능력 매핑 관리 UI는 제외한다.
10-7. 관리자 인증/권한 체계는 제외한다.
10-8. 커튼류 제품 배정은 본 단계에서 제외한다.
