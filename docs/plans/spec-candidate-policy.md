# 설치 기사 자동 배정 후보 정책

> 목적: 관리자 사전 승인 없는 자동 배정 요청 흐름에서 후보 선정과 차순위 진행 기준을 정의한다.
> 원칙: 후보 선정은 설명 가능하고 보수적으로 동작해야 하며, 불확실하면 자동 요청하지 않고 예외로 보낸다.

## 1. 정책 원칙

1-1. 시스템은 설치 예약 1건마다 설치 기사 후보를 선정한다.
1-2. 시스템은 선정된 1순위 설치 기사에게 자동으로 배정 요청을 발송한다.
1-3. 관리자는 기본 플로우에서 후보를 사전 승인하지 않는다.
1-4. 시스템은 후보 선정 근거를 설치건 상세에 기록한다.
1-5. 시스템은 자동 요청이 위험하거나 불확실한 경우 열린 예외를 생성해 수동 처리 필요로 표시한다.
1-6. 시스템은 후보 선정과 차순위 요청을 자동 재시도 한도 안에서만 수행한다.

## 2. 후보 선정 입력

2-1. 설치 예약의 제품 목록
2-2. 제품에서 산정한 필수 설치 능력
2-3. 제품에서 산정한 Aqara App 요구 등급
2-4. 설치 희망 날짜
2-5. 설치 방문 주소
2-6. 설치 방문 주소에서 추출한 표준 광역명과 시/구
2-7. 활성 설치 기사 목록
2-8. 설치 기사별 설치 능력
2-9. 설치 기사별 서비스 지역
2-10. 설치 기사별 Aqara App 대응 등급
2-11. 설치 기사별 월간 배정 건수
2-12. 설치 기사별 최근 자동 요청 시각
2-13. 같은 설치 예약에서 이미 요청했거나 제외된 설치 기사 목록
2-14. 설치 예약의 활성 배정 시도 여부
2-15. 설치 예약의 활성 배정 시도 유형
2-16. 설치 예약의 활성 배정 시도 상태
2-17. 설치 예약의 SMS 재시도 대기 여부

## 3. 자동 요청 금지 조건

3-1. 설치 희망 날짜가 없는 경우.
3-2. 설치 희망 날짜가 KST 기준 오늘로부터 2일 뒤보다 빠른 경우.
3-3. 설치 희망 날짜가 KST 기준 오늘로부터 30일 뒤보다 늦은 경우.
3-4. 설치 방문 주소를 표준 지역으로 파싱할 수 없는 경우.
3-5. 제품을 설치 능력 요구사항으로 변환할 수 없는 경우.
3-6. 필수 설치 능력을 충족하는 설치 기사가 없는 경우.
3-7. 지역 매칭 기준을 충족하는 설치 기사가 없는 경우.
3-8. 후보 선정 실행 중 데이터 정합성 오류가 발생한 경우.
3-9. 같은 설치 예약의 자동 재시도 한도를 이미 초과한 경우.
3-10. 설치 예약에 활성 배정 시도가 있는 경우.
3-11. 설치 예약 상태가 자동 요청 가능한 상태가 아닌 경우.

## 4. 제품 요구 능력 산정

4-1. 시스템은 ERP `items_json` 원문을 `sourceItemsJsonText`로 저장한다.
4-2. 시스템은 `sourceItemsJsonText`의 전체 품목을 기준으로 필수 설치 능력 목록을 산정해 `requiredCapabilities`로 저장한다.
4-3. 여러 품목이 있으면 필수 설치 능력은 합집합으로 산정한다.
4-4. Aqara App 요구 등급은 ERP 조회 단계에서 산정한 `requiredAqaraAppCapability`를 저장한다.
4-5. `sourceMemo`는 표시용 제품 요약이며 필수 설치 능력 또는 Aqara App 요구 등급 산정에 사용하지 않는다.
4-6. 저장된 필수 설치 능력이 없으면 자동 요청하지 않고 수동 처리로 전환한다.

## 5. 주소 표준화

5-1. 시스템은 설치 방문 주소에서 표준 광역명을 추출한다.
5-2. 시스템은 설치 방문 주소에서 표준 시/구를 추출한다.
5-3. 시스템은 광역명과 시/구를 결합해 지역 key를 만든다.
5-4. 표준 지역을 만들 수 없으면 자동 요청하지 않고 수동 처리로 전환한다.
5-5. 주문 배송지 주소 폴백을 사용한 경우에도 동일한 표준화 과정을 적용한다.

## 6. 후보 필터링

6-1. 활성 상태인 설치 기사만 후보에 포함한다.
6-2. 필수 설치 능력을 모두 가진 설치 기사만 후보에 포함한다.
6-3. Aqara App 요구 등급을 충족하는 설치 기사만 후보에 포함한다.
6-4. 지역 매칭에서 `REGION_ONLY` 이상을 충족하는 설치 기사만 후보에 포함한다.
6-5. 같은 설치 예약에서 이미 요청한 설치 기사는 차순위 후보에서 제외한다.
6-6. 관리자가 특정 설치 기사를 제외한 경우 해당 설치 기사는 후보에서 제외한다.
6-7. Aqara 허브 재고 보유 여부는 후보 필터링에 사용하지 않는다.

## 7. 지역 매칭 tier

7-1. `EXACT_DISTRICT`: 설치 예약의 지역 key가 설치 기사 서비스 지역에 정확히 포함된 경우.
7-2. `REGION_ONLY`: 정확한 시/구 매칭은 없지만 설치 예약 광역명과 설치 기사 서비스 광역명이 같은 경우.
7-3. 설치 기사 서비스 지역이 광역 단위로만 등록된 경우 같은 광역명은 `REGION_ONLY`로 본다.
7-4. `EXACT_DISTRICT`는 `REGION_ONLY`보다 항상 우선한다.
7-5. 두 tier 모두 충족하지 못하는 설치 기사는 후보에서 제외한다.

## 8. 후보 정렬

8-1. `EXACT_DISTRICT` 후보를 `REGION_ONLY` 후보보다 우선한다.
8-2. 같은 tier 안에서는 월간 배정 건수가 적은 설치 기사를 우선한다.
8-3. 월간 배정 건수가 같으면 최근 요청 시각이 오래된 설치 기사를 우선한다.
8-4. 최근 요청 이력이 없는 설치 기사는 최근 요청 시각이 가장 오래된 것으로 본다.
8-5. 최근 요청 시각도 같으면 설치 기사 ID 기준 안정 정렬을 적용한다.
8-6. 설치 기사 평점, 임의 가중치, 재고 보유 여부는 정렬에 사용하지 않는다.

## 9. 후보 선정 결과 기록

9-1. 시스템은 후보 선정 실행 입력 snapshot을 기록한다.
9-2. 시스템은 후보별 순위, 지역 tier, 월간 배정 건수, 최근 요청 시각, 판단 근거를 기록한다.
9-3. 시스템은 자동 요청 대상이 된 후보와 제외된 후보를 구분해 기록한다.
9-4. 후보가 없으면 후보 없음 사유를 기록하고 예외를 만든다.
9-5. 입력 정보 부족, 정책 데이터 오류, 데이터 정합성 오류, 필터링 결과 없음은 서로 다른 사유로 기록한다.
9-6. 설치건 상세는 현재 후보와 과거 후보 선정 실행을 모두 확인할 수 있게 한다.

## 10. 관리자 검토와 요청 발송 정책

10-1. 후보가 있으면 시스템은 1순위 후보를 배정 시도 `WAITING_ADMIN_REVIEW`로 기록하고 설치 예약을 `WAITING_ADMIN_REVIEW` 상태로 전환한다.
10-2. 시스템은 관리자 승인 전에는 기사에게 배정 요청 SMS를 발송하지 않는다.
10-3. 후보 선정 전 시스템은 설치 예약 상태, 활성 배정 시도 여부, 활성 배정 시도 유형, 활성 배정 시도 상태, SMS 재시도 대기 여부를 다시 확인한다.
10-4. 자동 후보 선정은 설치 예약 상태가 `READY_FOR_CANDIDATE_SELECTION`이고, 활성 배정 시도가 없고, SMS 재시도 대기 상태가 아닐 때만 실행할 수 있다.
10-5. 설치 예약에 활성 배정 시도가 있으면 새 후보 선정 또는 새 요청을 실행하지 않는다.
10-6. 활성 배정 시도가 없더라도 SMS 재시도 대기 상태이면 새 후보 선정 또는 새 요청을 실행하지 않고 기존 배정 시도 SMS 재시도만 수행한다.
10-7. 요청 발송 전 상태가 `CANCELLED` 또는 `COMPLETED`이면 요청하지 않는다.
10-8. 관리자가 후보를 승인하면 시스템은 배정 요청 SMS를 발송한다.
10-9. 요청 발송 성공 후 설치 예약은 `WAITING_INSTALLER_RESPONSE` 상태가 되고 활성 배정 시도 상태는 `WAITING_INSTALLER_RESPONSE`가 된다.
10-10. 요청 발송 실패가 일시 오류면 설치 예약 상태는 `WAITING_ADMIN_REVIEW`로 유지하고 같은 배정 시도 상태를 `SYSTEM_SMS_RETRY_PENDING`으로 기록한다.
10-11. SMS 재시도 중에는 같은 설치 예약에 다른 자동 배정 요청을 발송하지 않는다.
10-12. 요청 발송 실패가 복구되지 않으면 활성 배정 시도를 `SYSTEM_SMS_FAILED`로 종료하고 SMS 실패 예외를 만들어 수동 처리 필요로 표시한다.

## 11. 차순위 후보 정책

11-1. 자동 배정 요청에서 설치 기사가 거절하면 시스템은 차순위 후보를 찾는다.
11-2. 자동 배정 요청에서 설치 기사가 제한 시간 안에 응답하지 않으면 timeout 처리 후 차순위 후보를 찾는다.
11-3. 이전 후보 선정 결과에 남은 후보가 있으면 다음 순위 후보를 사용한다.
11-4. 시스템은 차순위 후보에게 요청하기 직전에 기사 활성 상태, 필수 설치 능력, Aqara App 대응 등급, 서비스 지역을 다시 검증한다.
11-5. 재검증을 통과하지 못한 설치 기사는 차순위 요청 대상에서 제외하고 제외 사유를 기록한다.
11-6. 이전 후보 결과를 사용할 수 없거나 남은 후보가 모두 재검증에 실패하면 새 후보 선정 실행을 기록한다.
11-7. 이미 요청한 설치 기사는 새 후보 선정에서도 제외한다.
11-8. 차순위 후보가 있으면 시스템은 설치 예약을 `WAITING_ADMIN_REVIEW` 상태로 전환하고 관리자 승인을 기다린다.
11-9. 차순위 후보가 없으면 후보 소진 예외를 만들어 수동 처리 필요로 표시한다.
11-10. 관리자 직접 지정 요청과 관리자 재실행 요청이 거절 또는 timeout으로 종료된 경우 이 차순위 후보 정책을 적용하지 않는다.

## 12. 자동 재시도 한도

12-1. 자동 요청은 설치 예약 1건당 최초 요청과 자동 재시도 1회를 합쳐 최대 2명의 설치 기사에게 발송할 수 있다.
12-2. 2번째 자동 요청까지는 자동 진행 범위에 포함한다.
12-3. 2번째 자동 요청이 거절 또는 timeout으로 종료되면 시스템은 열린 예외로 수동 처리 필요를 표시한다.
12-4. 관리자 직접 지정 요청은 자동 재시도 한도에 포함하지 않는다.
12-5. 동일 기사에게 같은 설치 예약 요청을 중복 발송하지 않는다.

## 13. 관리자 직접 지정 정책

13-1. 관리자는 열린 예외가 있는 수동 처리 필요 설치 예약에 직접 설치 기사를 지정할 수 있다.
13-2. 관리자 직접 지정은 지역 tier, 월간 배정 건수, 최근 요청 시각 정렬을 우회할 수 있다.
13-3. 관리자 직접 지정이라도 비활성 설치 기사는 지정할 수 없다.
13-4. 관리자 직접 지정이라도 필수 설치 능력을 충족하지 못하는 설치 기사는 지정할 수 없다.
13-5. 관리자 직접 지정이라도 Aqara App 요구 등급을 충족하지 못하는 설치 기사는 지정할 수 없다.
13-6. 관리자가 지역 매칭 기준을 충족하지 못하는 설치 기사를 지정하려면 수동 지정 사유를 기록해야 한다.
13-7. 관리자 직접 지정 요청도 동일 기사 중복 발송 금지 정책을 따른다.
13-8. 관리자 직접 지정 요청이 거절 또는 timeout으로 종료되면 시스템은 차순위 자동 요청을 진행하지 않고 설치 예약을 수동 처리 필요로 표시한다.
13-9. 관리자 직접 지정 요청 SMS 발송 실패가 복구되지 않으면 시스템은 SMS 실패 예외를 만들어 수동 처리 필요로 표시한다.

## 14. 동시 실행 및 중복 방지

14-1. 시스템은 설치 예약 1건에 대해 동시에 하나의 활성 배정 시도만 허용한다.
14-2. 후보 선정과 요청 발송은 같은 설치 예약 기준으로 원자적으로 처리한다.
14-3. Cron 또는 dispatcher가 중복 실행돼도 같은 설치 예약에 두 명 이상의 설치 기사에게 동시에 자동 요청하지 않는다.
14-4. 배정 요청 SMS는 배정 시도 ID 기준으로 멱등하게 발송한다.
14-5. 이미 발송 성공 처리된 배정 시도는 같은 SMS를 자동으로 재발송하지 않는다.
14-6. SMS 재시도는 발송 실패로 기록된 같은 배정 시도에 대해서만 수행한다.
14-7. dispatcher는 설치 예약 상태만으로 자동 요청 가능 여부를 판단하지 않고, 활성 배정 시도 유형, 활성 배정 시도 상태, SMS 재시도 대기 여부를 함께 확인한다.

## 15. 설치 기사 정보 노출

15-1. 수락 전 설치 기사 화면에는 설치 희망 날짜, 상세 설치 방문 주소, 고객 전화번호, 제품 요약, 필수 설치 능력을 표시한다.
15-2. 수락 전 고객 전체 이름은 표시하지 않는다.
15-3. 수락 후에도 고객 연락처와 상세 설치 방문 주소를 표시할 수 있다.
15-4. 거절 또는 timeout된 요청 링크는 고객 상세 정보를 표시하지 않는다.

## 16. 제외 정책

16-1. 설치 주문 통합 배정은 하지 않는다.
16-2. 지도 API 기반 거리 계산은 하지 않는다.
16-3. 비용 산정은 하지 않는다.
16-4. 설치 기사 평점 기반 우선순위는 사용하지 않는다.
16-5. 설치 기사 시간대 충돌은 판단하지 않는다.
16-6. Aqara 허브 재고 보유 여부는 필터나 정렬에 사용하지 않는다.
16-7. 커튼류 제품 배정은 본 단계에서 제외한다.
