# 페이지 정의

> 기준 문서: `docs/plans/spec-feature-list.md`, `docs/plans/spec-flow-state.md`, `docs/plans/spec-candidate-policy.md`
> 목적: 고객, 관리자, 설치 기사가 각 페이지에서 무엇을 보고 어떤 액션을 수행하는지 정의한다.
> 구현 호출 순서: `docs/plans/spec-page-implementation.md`

## 1. 페이지 정의 원칙

1-1. 페이지는 설치 주문, 설치 예약, 설치건의 책임을 구분해 표시한다.
1-2. 고객 페이지는 설치 예약 입력과 제출 완료 확인만 제공한다.
1-3. 관리자 페이지의 중심 경로는 `/backoffice/installations`이다.
1-4. 관리자 설치 주문 페이지는 설치 주문 목록, 배정 요청 목록, 설치건 상세 진입을 제공한다.
1-5. 관리자 설치건 상세는 `/backoffice/installations/:installationId` 경로로 제공한다.
1-6. 관리자 예외 목록은 독립 페이지로 제공하지 않고 설치 주문 목록과 설치건 상세의 예외 표시로 제공한다.
1-7. 설치 기사 페이지는 배정 요청 확인과 설치 기사 배정 수락 또는 거절 응답만 제공한다.
1-8. 시스템이 자동으로 수행하는 설치 기사 후보 선정 정책은 페이지에서 수정하지 않는다.
1-9. `installationId`는 내부 설치건 식별자이며 DB 기준으로는 설치 예약 ID다.
1-10. 설치 주문 키는 제품 주문 ID와 원천 주문 번호를 포함하는 원천 주문 식별자이며 목록과 상세에서 표시 및 검색 대상으로 사용한다.
1-11. 관리자 설치건 상세는 원천 주문, 고객 입력, 후보 선정, 배정 시도, SMS, 예외, 감사 이력을 한 설치건 기준으로 확인할 수 있게 구성한다.
1-12. 관리자 설치건 상세는 주문 진행 상태, 주문 정보, 고객 요청, 기사 후보/배정, SMS, 예외, 진행 이력 탭으로 구분한다.
1-13. 고객 설치 예약 입력 페이지는 `/i/c/{token}` 경로로 제공한다.
1-14. 설치 기사 배정 요청 응답 페이지는 `/i/i/{token}` 경로로 제공한다.

## 2. 고객 설치 예약 입력 페이지

2-1. 고객은 `/i/c/{token}` 설치 예약 링크로 페이지에 접근한다.
2-2. 시스템은 고객 토큰 유효성과 만료 여부를 검증한다.
2-3. 시스템은 고객 토큰이 만료됐거나 유효하지 않거나 이미 제출된 경우 입력 폼 대신 `이미 접수되었거나 유효하지 않은 정보` 상태를 표시한다.
2-4. 고객은 설치 희망 날짜를 입력한다.
2-5. 고객은 설치 방문 주소를 입력한다.
2-6. 고객은 연락처를 입력한다.
2-7. 고객은 메모(선택)를 입력할 수 있다.
2-8. 시스템은 설치 희망 날짜와 설치 방문 주소를 검증한다.
2-9. 시스템은 설치 희망 날짜를 선택할 수 없거나 설치 방문 주소를 파싱할 수 없으면 입력 오류 메시지를 표시한다.
2-10. 시스템은 제출 성공 시 설치 예약을 설치 기사 후보 선정 가능 상태로 전환한다.
2-11. 시스템은 제출 성공 후 설치 기사 배정이 진행될 예정임을 고객에게 안내한다.
2-12. 시스템은 제출 직후에는 `입력 완료` 상태를 표시한다.
2-13. 시스템은 제출 완료 후 재접근 시 `이미 접수되었거나 유효하지 않은 정보` 상태를 표시하고 재제출을 막는다.
2-14. 고객 설치 예약 입력 페이지의 사용자 표시 단계는 `입력`, `입력 완료`, `이미 접수되었거나 유효하지 않은 정보`, `오류` 네 가지로 제한한다.

## 3. 관리자 설치 주문 페이지

3-1. 시스템은 `/backoffice/installations`에서 관리자에게 설치건 목록을 표시한다.
3-2. 시스템은 설치 주문 탭과 배정 요청 탭을 제공한다.
3-3. 시스템은 설치 주문 목록에서 고객명 또는 전화번호 정확 일치 검색을 제공한다.
3-4. 시스템은 설치 주문 키, 제품, 메모, 고객명, 전화번호, 설치 주소, 주소 출처, 상태, 예외, 희망일, 긴급도, 고객 요청 상태, 최근 배정 정보를 목록 컬럼으로 표시한다.
3-5. 시스템은 설치 주문 목록에서 컬럼 정렬, 컬럼 표시 여부, 컬럼 순서, 컬럼 크기 조정을 제공한다.
3-6. 시스템은 설치 주문 목록에서 페이지 크기, 이전 페이지, 다음 페이지 탐색을 제공한다.
3-7. 시스템은 각 설치건의 설치 주문 정보 요약을 표시한다.
3-8. 시스템은 각 설치건의 설치 예약 정보 요약을 표시한다.
3-9. 시스템은 각 설치건의 최근 배정 기사, 배정 차수, 배정 유형, 배정 상태를 표시한다.
3-10. 시스템은 후보 없음, 후보 소진, 고객 정보 부족, 설치 희망 날짜 임박, SMS 실패 예외를 설치건 목록 안에 표시한다.
3-11. 관리자는 설치건을 선택해 `/backoffice/installations/:installationId` 상세로 이동한다.
3-12. 시스템은 목록에서 설치건의 현재 상태를 우선 표시하고, 상세에서 전체 진행 과정을 확인하도록 유도한다.
3-13. 시스템은 배정 요청 탭에서 응답 대기 중인 기사 배정 요청 목록을 표시한다.

## 4. 관리자 ERP 주문 데이터 페이지

4-1. 시스템은 `/backoffice/installation-order-source`에서 관리자에게 ERP 주문 데이터 조회 결과를 표시한다.
4-2. 시스템은 페이지 접근 시 관리자 인증과 권한을 검증한다.
4-3. 시스템은 ERP에서 설치 주문 원천 데이터를 조회한다.
4-4. 시스템은 조회한 원천 데이터를 ERP 주문 데이터 테이블 표시 형식으로 정규화한다.
4-5. 시스템은 정규화한 ERP 주문 데이터에 원천 데이터 검증 결과를 주석 처리한다.
4-6. 시스템은 ERP 주문 데이터를 테이블로 렌더링한다.

## 5. 관리자 설치건 상세 페이지

5-1. 시스템은 `/backoffice/installations/:installationId`에서 관리자에게 설치건 상세를 표시한다.
5-2. 시스템은 관리자에게 설치 주문 정보를 표시한다.
5-3. 시스템은 관리자에게 설치 예약 정보를 표시한다.
5-4. 시스템은 관리자에게 현재 설치 기사 후보를 표시한다.
5-5. 시스템은 관리자에게 설치 기사 후보 선정 근거를 표시한다.
5-6. 시스템은 관리자에게 배정 시도와 설치 기사 응답 이력을 표시한다.
5-7. 시스템은 관리자에게 해당 설치건의 예외 내용을 표시한다.
5-8. 시스템은 관리자에게 고객 입력 또는 주문 배송지 폴백 여부를 표시한다.
5-9. 시스템은 관리자에게 후보 선정 실행 시각, 후보 순위, 지역 tier, 월간 배정 건수, 판단 근거를 표시한다.
5-10. 시스템은 관리자에게 고객/기사 SMS 발송 이력과 실패 사유를 표시한다.
5-11. 시스템은 관리자에게 상태 변경과 주요 액션을 시간순 타임라인으로 표시한다.
5-12. 시스템은 타임라인 문구를 감사 이력의 이벤트 타입과 metadata를 기반으로 렌더링한다.
5-13. 시스템은 주문 진행 상태 탭에서 현재 상태, 현재 기사, 주문번호, 상태 액션을 표시한다.
5-14. 시스템은 주문 정보 탭에서 고객 정보, 주소, 상품 및 설치 요구, 원천 주문 정보를 표시한다.
5-15. 시스템은 고객 요청 탭에서 고객 입력 요청 이력을 표시한다.
5-16. 시스템은 기사 후보/배정 탭에서 후보 선정 결과, 현재 기사 후보, 배정 시도, 기사 응답 이력을 표시한다.
5-17. 시스템은 SMS 탭에서 고객/기사 SMS 발송 이력, 실패 사유, 재시도 가능 여부를 표시한다.
5-18. 시스템은 예외 탭에서 현재 미해결 예외와 과거 해결 이력을 구분해 표시한다.
5-19. 시스템은 진행 이력 탭에서 상태 변경과 주요 액션을 시간순으로 표시한다.
5-20. 시스템은 후보 선정 결과를 관리자 승인 단계로 표시하고, 관리자는 후보 승인 후 기사 배정 요청 SMS를 발송할 수 있다.
5-21. 관리자는 SMS 실패 건의 재발송을 실행할 수 있다.
5-22. 시스템은 SMS 재발송 실행 시 재시도 결과와 실패 사유를 SMS 탭과 진행 이력에 기록한다.
5-23. 관리자는 열린 예외가 있는 수동 처리 필요 설치건에 직접 설치 기사를 지정해 배정 요청 SMS를 발송할 수 있다.
5-24. 관리자는 직접 지정 시 지역 매칭 기준을 충족하지 못하는 설치 기사를 지정하려면 수동 지정 사유를 입력한다.
5-25. 관리자는 수동 처리 필요 건에서 후보 선정 재시도를 실행할 수 있다.
5-26. 관리자는 `READY_FOR_CANDIDATE_SELECTION` 또는 `WAITING_INSTALLER_RESPONSE` 상태의 설치건을 수동 처리로 전환할 수 있다.
5-27. 시스템은 관리자 수동 처리 전환 시 활성 자동 배정 시도를 `ADMIN_MANUAL_OVERRIDDEN`으로 종료하고 관리자 ID, 전환 시각, 수동 전환 사유를 기록한다.
5-28. 관리자는 설치 완료 또는 이미 취소된 설치건이 아닌 경우 설치건 취소를 실행할 수 있다.
5-29. 시스템은 설치건 취소 실행 전 확인 단계를 표시한다.
5-30. 관리자는 설치건 취소 시 취소 사유를 선택한다.
5-31. 시스템은 취소 사유가 주문건 취소인 경우에도 원천 주문 시스템에 주문 취소를 요청하지 않는다.
5-32. 관리자는 현재 상태와 관계없이 설치 완료를 확정할 수 있다.
5-33. 시스템은 설치 완료 확정 전 확인 단계를 표시한다.
5-34. 시스템은 설치 완료 확정 시 활성 배정 시도가 있으면 `ADMIN_COMPLETED`로 종료하고 완료 처리 관리자 ID, 완료 시각, 완료 사유를 기록한다.

## 6. 설치 기사 배정 요청 응답 페이지

6-1. 설치 기사는 `/i/i/{token}` 배정 요청 SMS의 토큰 링크로 페이지에 접근한다.
6-2. 시스템은 설치 기사 토큰 유효성과 만료 여부를 검증한다.
6-3. 시스템은 설치 기사 토큰이 만료됐거나 유효하지 않거나 이미 응답된 경우 응답 폼 대신 `이미 응답했거나 유효하지 않은 정보` 상태를 표시한다.
6-4. 시스템은 설치 기사 배정 수락 전 설치 희망 날짜, 대략 지역, 제품 요약, 필수 설치 능력을 표시한다.
6-5. 시스템은 설치 기사 배정 수락 전 고객 전체 이름, 전화번호, 상세 설치 방문 주소를 노출하지 않는다.
6-6. 설치 기사는 설치 기사 배정 수락 응답을 제출한다.
6-7. 설치 기사는 설치 기사 배정 거절 응답을 제출한다.
6-8. 시스템은 설치 기사 배정 수락 응답을 받으면 설치 예약을 `INSTALLER_ASSIGNED` 상태로 전환하고 현재 배정 시도를 `INSTALLER_ACCEPTED`로 기록한다.
6-9. 시스템은 설치 기사 배정 수락 후 고객 배정 확정 SMS와 기사 해피콜 안내 SMS를 예약한다.
6-10. 시스템은 설치 기사 배정 거절 응답을 받으면 거절 사유를 기록하고 현재 배정 시도를 `INSTALLER_REJECTED`로 기록한다.
6-11. 거절 또는 timeout 후 활성 배정 시도 유형이 `AUTO`이면 시스템은 차순위 후보 플로우로 이동한다.
6-12. 거절 또는 timeout 후 활성 배정 시도 유형이 `MANUAL_DIRECT` 또는 `ADMIN_RETRY`이면 시스템은 차순위 자동 요청을 진행하지 않고 설치 예약을 수동 처리 필요로 표시한다.
6-13. 설치 기사 배정 요청 응답 페이지의 사용자 표시 단계는 `응답`, `응답 완료`, `이미 응답했거나 유효하지 않은 정보`, `오류` 네 가지로 제한한다.

## 7. 제외 페이지

7-1. 시스템은 고객 진행 상황 페이지를 제공하지 않는다.
7-2. 시스템은 설치 기사 전용 워크스테이션을 제공하지 않는다.
7-3. 시스템은 제품-설치 능력 매핑 관리 UI를 제공하지 않는다.
7-4. 시스템은 설치 기사 프로필 관리 페이지를 제공하지 않는다.
7-5. 시스템은 설치 기사 후보 선정 정책 편집 페이지를 제공하지 않는다.
7-6. 시스템은 관리자 예외 목록 독립 페이지를 제공하지 않는다.
7-7. 시스템은 관리자 로그인, 인증, 세션, 권한 관리 페이지를 제공하지 않는다.
