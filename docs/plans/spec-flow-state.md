# 설치 배정 플로우와 상태

> 목적: 설치 예약이 어떤 상태를 거쳐 배정 요청, 기사 응답, 예외 처리, 취소, 완료로 이어지는지 정의한다.
> 원칙: 상태는 “다음 책임 주체”와 “자동 진행 가능 여부”를 기준으로 나눈다.

## 1. 처리 단위

1-1. 설치 주문은 외부 주문 시스템에서 들어온 원천 주문이다.
1-2. 설치 예약은 고객 입력과 배정 진행을 관리하는 내부 단위다.
1-3. 설치건은 관리자가 보는 업무 단위이며 설치 예약과 1:1로 대응한다.
1-4. 시스템은 설치 주문 1건마다 설치 예약 1건을 생성한다.
1-5. 시스템은 설치 예약 1건 단위로 후보 선정, 기사 요청, 차순위 진행, 예외 처리를 수행한다.
1-6. 설치 주문 수집 실패나 개별 설치 예약 실패는 다른 설치 예약 처리에 영향을 주지 않는다.

## 2. 상태 목록

| 상태 | 책임 주체 | 의미 |
|---|---|---|
| `CUSTOMER_INPUT_SMS_REQUIRED` | 시스템 | 고객 설치 정보 입력 SMS 발송 필요 |
| `WAITING_CUSTOMER_INPUT` | 고객 | 고객 설치 정보 입력 대기 |
| `READY_FOR_CANDIDATE_SELECTION` | 시스템 | 후보 선정 가능. 자동 새 후보 선정은 활성 배정 시도가 없고 SMS 재시도 대기가 아닐 때만 가능 |
| `WAITING_ADMIN_REVIEW` | 관리자 | 시스템이 후보를 선정했고 관리자 승인 대기 |
| `WAITING_INSTALLER_RESPONSE` | 설치 기사 | 특정 기사에게 요청 발송 후 응답 대기 |
| `INSTALLER_ASSIGNED` | 시스템/관리자 | 설치 기사가 수락해 배정 완료 |
| `CANCELLED` | 관리자 | 설치건 취소로 자동 진행 종료 |
| `COMPLETED` | 관리자/운영 | 설치 완료로 종료 |

수동 처리 필요는 설치 예약 상태 enum이 아니라 `hasOpenIssue=true`, 열린 예외, 활성 배정 해제, 감사 이벤트로 표현한다.

## 3. 관리자 검토 정책

3-1. 설치 기사 후보 검토 대기 상태는 기본 플로우에 포함한다.
3-2. 시스템은 후보 선정 후 `WAITING_ADMIN_REVIEW` 상태로 전환하고 기사에게 SMS를 발송하지 않는다.
3-3. 관리자가 후보를 승인해야 배정 요청 SMS를 발송한다.
3-4. 후보 검토 화면은 필수 진행 단계이며 승인, 수동 처리 전환, 후보 재탐색을 제공한다.
3-5. 관리자는 슈퍼 권한을 가지며 현재 상태와 관계없이 설치 완료 처리를 수행할 수 있다.

## 4. 배정 시도 판별 필드

4-1. 시스템은 설치 예약 상태와 별도로 활성 배정 시도 여부를 관리한다.
4-2. 활성 배정 시도는 유형을 가진다. 유형 값은 `AUTO`, `MANUAL_DIRECT`, `ADMIN_RETRY` 중 하나다.
4-3. 활성 배정 시도는 상태를 가진다. 상태 값은 `WAITING_ADMIN_REVIEW`, `WAITING_INSTALLER_RESPONSE`, `SYSTEM_SMS_RETRY_PENDING` 중 하나다.
4-4. 종료된 배정 시도 상태는 `INSTALLER_ACCEPTED`, `INSTALLER_REJECTED`, `INSTALLER_RESPONSE_TIMED_OUT`, `SYSTEM_SMS_FAILED`, `ADMIN_MANUAL_OVERRIDDEN`, `ADMIN_COMPLETED` 중 하나다.
4-5. 시스템은 자동 새 요청 가능 여부를 설치 예약 상태만으로 판단하지 않고 활성 배정 시도 여부, 활성 배정 시도 유형, 활성 배정 시도 상태, SMS 재시도 대기 여부를 함께 확인한다.
4-6. 설치 예약 상태가 `READY_FOR_CANDIDATE_SELECTION`이어도 활성 배정 시도 상태가 `SYSTEM_SMS_RETRY_PENDING`이면 새 후보 선정, 새 자동 요청, 차순위 진행을 실행하지 않고 같은 배정 시도 SMS 재시도만 수행한다.
4-7. 설치 예약 상태가 `WAITING_ADMIN_REVIEW`이면 관리자 승인 전까지 기사에게 배정 요청 SMS를 발송하지 않는다.

## 5. 메인 플로우

5-1. 시스템이 신규 설치 주문을 수집한다.
5-2. 시스템이 중복 주문을 제외하고 설치 예약을 생성한다.
5-3. 시스템이 고객에게 설치 정보 입력 SMS를 보낸다.
5-4. 설치 예약은 `WAITING_CUSTOMER_INPUT` 상태가 된다.
5-5. 고객이 설치 희망 날짜, 설치 방문 주소, 연락처를 제출한다.
5-6. 고객 입력 검증에 실패하면 시스템은 제출을 저장하지 않고 고객 입력 화면에서 오류를 표시한다.
5-7. 고객 입력 검증 실패만으로 설치 예약 상태를 변경하지 않는다.
5-8. 고객 입력 검증에 성공하면 시스템이 설치 요구 능력과 지역 key를 산정한다.
5-9. 설치 예약은 `READY_FOR_CANDIDATE_SELECTION` 상태가 된다.
5-10. 시스템은 설치 예약 상태가 `READY_FOR_CANDIDATE_SELECTION`이고 활성 배정 시도가 없고 SMS 재시도 대기가 아닐 때 후보 선정 정책을 실행한다.
5-11. 후보가 있으면 시스템은 1순위 후보를 활성 배정 시도 `WAITING_ADMIN_REVIEW`로 기록한다.
5-12. 설치 예약은 `WAITING_ADMIN_REVIEW` 상태가 되고 관리자 검토를 기다린다.
5-13. 관리자가 후보를 승인하면 시스템은 배정 요청 SMS를 발송한다.
5-14. 배정 요청 SMS 발송에 성공하면 설치 예약은 `WAITING_INSTALLER_RESPONSE` 상태가 되고 활성 배정 시도 상태는 `WAITING_INSTALLER_RESPONSE`가 된다.
5-15. 배정 요청 SMS 발송이 일시 실패하면 설치 예약은 `WAITING_ADMIN_REVIEW` 상태를 유지하고 같은 배정 시도 상태를 `SYSTEM_SMS_RETRY_PENDING`으로 기록한다.
5-16. SMS 재시도 대기 중에는 새 후보 선정, 새 자동 요청, 차순위 진행을 실행하지 않는다.
5-17. 배정 요청 SMS 발송 실패가 복구되지 않으면 활성 배정 시도를 `SYSTEM_SMS_FAILED`로 종료하고 설치 예약은 열린 SMS 실패 예외를 가진 수동 처리 필요 설치건이 된다.
5-18. 설치 기사가 수락하면 설치 예약은 `INSTALLER_ASSIGNED` 상태가 된다.
5-19. 시스템은 고객에게 배정 완료 SMS를 발송한다.
5-20. 시스템은 설치 기사에게 해피콜 안내 SMS를 발송한다.
5-21. 관리자는 현재 상태와 관계없이 설치 완료를 확인하면 `COMPLETED` 상태로 전환한다.

## 6. 고객 입력 지연 플로우

6-1. 고객 입력 기한은 고객 입력 링크 발송 시각부터 48시간으로 한다.
6-2. 고객이 링크 발송 후 24시간 안에 입력하지 않으면 시스템은 리마인드 SMS를 1회 발송한다.
6-3. 고객 입력 요청 생성 직후에는 주문 배송지 주소, 주문 전화번호, 원천 설치 희망일을 실제 설치 정보로 저장하지 않는다.
6-4. 고객이 링크 발송 후 96시간 안에 입력하지 않으면 시스템은 주문 배송지 주소와 주문 전화번호를 실제 설치 정보로 폴백한다.
6-5. 폴백 시 원천 주문 설치 희망 날짜가 KST 기준 오늘로부터 2일 뒤부터 30일 뒤까지의 범위 안이면 해당 날짜를 사용한다.
6-6. 폴백 후 설치 희망 날짜와 주소가 유효하면 `READY_FOR_CANDIDATE_SELECTION` 상태로 전환한다.
6-7. 폴백 후에도 설치 정보가 부족하면 상태 값은 유지하고 고객 정보 부족 예외를 열어 수동 처리 필요로 표시한다.

## 7. 기사 응답 플로우

7-1. 설치 기사는 SMS 토큰 링크로 요청 상세에 접근한다.
7-2. 시스템은 토큰 유효성과 요청 상태를 검증한다.
7-3. 설치 기사가 수락하면 현재 배정 시도를 `INSTALLER_ACCEPTED`로 기록한다.
7-4. 시스템은 설치 예약을 `INSTALLER_ASSIGNED` 상태로 전환한다.
7-5. 설치 기사가 거절하면 현재 배정 시도를 `INSTALLER_REJECTED`로 기록한다.
7-6. 설치 기사 응답 제한 시간은 배정 요청 SMS 발송 성공 시각부터 24시간으로 한다.
7-7. 설치 기사가 제한 시간 안에 응답하지 않으면 현재 배정 시도를 `INSTALLER_RESPONSE_TIMED_OUT`으로 기록한다.
7-8. 거절 또는 timeout 후 활성 배정 시도 유형이 `AUTO`이면 시스템은 차순위 후보를 찾는다.
7-9. 거절 또는 timeout 후 활성 배정 시도 유형이 `MANUAL_DIRECT`이면 시스템은 차순위 자동 요청을 진행하지 않고 설치 예약을 수동 처리 필요로 표시한다.
7-10. 거절 또는 timeout 후 활성 배정 시도 유형이 `ADMIN_RETRY`이면 시스템은 차순위 자동 요청을 진행하지 않고 설치 예약을 수동 처리 필요로 표시한다.

## 8. 차순위 자동 진행 플로우

8-1. 시스템은 이미 요청했던 설치 기사를 제외한다.
8-2. 시스템은 이전 후보 선정 결과의 다음 순위 후보를 우선 사용한다.
8-3. 시스템은 차순위 후보에게 요청하기 직전에 기사 활성 상태, 필수 설치 능력, Aqara App 대응 등급, 서비스 지역을 다시 검증한다.
8-4. 재검증을 통과하지 못한 설치 기사는 차순위 요청 대상에서 제외하고 제외 사유를 기록한다.
8-5. 이전 후보 결과를 재사용할 수 없거나 남은 후보가 모두 재검증에 실패하면 새 후보 선정 실행을 기록한다.
8-6. 차순위 후보가 있으면 시스템은 새 활성 배정 시도를 `WAITING_ADMIN_REVIEW`로 기록하고 설치 예약을 `WAITING_ADMIN_REVIEW` 상태로 전환한다.
8-7. 관리자가 차순위 후보를 승인하면 배정 요청 SMS를 발송하고, 성공 시 설치 예약은 `WAITING_INSTALLER_RESPONSE` 상태가 된다.
8-8. 차순위 배정 요청 SMS 발송이 일시 실패하면 설치 예약은 `WAITING_ADMIN_REVIEW` 상태로 전환하고 같은 배정 시도 상태를 `SYSTEM_SMS_RETRY_PENDING`으로 기록한다.
8-9. SMS 재시도 대기 중에는 새 후보 선정, 새 자동 요청, 추가 차순위 진행을 실행하지 않는다.
8-10. 차순위 배정 요청 SMS 발송 실패가 복구되지 않으면 활성 배정 시도를 `SYSTEM_SMS_FAILED`로 종료하고 설치 예약은 열린 SMS 실패 예외를 가진 수동 처리 필요 설치건이 된다.
8-11. 3번째 자동 요청이 거절 또는 timeout으로 종료되면 시스템은 설치 예약을 수동 처리 필요로 표시한다.
8-12. 후보가 소진되면 후보 소진 예외를 열어 수동 처리 필요로 표시한다.

## 9. 수동 처리 플로우

9-1. 관리자는 `READY_FOR_CANDIDATE_SELECTION`, `WAITING_ADMIN_REVIEW`, `WAITING_INSTALLER_RESPONSE` 상태의 설치 예약을 수동 처리로 전환할 수 있다.
9-2. 관리자가 수동 처리로 전환하면 시스템은 활성 자동 배정 시도를 `ADMIN_MANUAL_OVERRIDDEN`으로 종료하고 설치 예약의 상태 값은 유지한 채 열린 예외로 수동 처리 필요를 표시한다.
9-3. 시스템은 수동 처리 전환 시 관리자 ID, 전환 시각, 수동 전환 사유를 감사 이력에 기록한다.
9-4. 수동 처리 전환은 고객이나 설치 기사에게 자동 SMS를 발송하지 않는다.
9-5. 관리자는 열린 예외가 있는 수동 처리 필요 설치건을 예외 보드에서 확인한다.
9-6. 관리자는 직접 설치 기사를 지정해 배정 요청 SMS를 발송할 수 있다.
9-7. 관리자 직접 지정은 비활성 설치 기사, 필수 설치 능력 미충족 설치 기사, Aqara App 요구 등급 미충족 설치 기사를 허용하지 않는다.
9-8. 관리자가 지역 매칭 기준을 충족하지 못하는 설치 기사를 지정하려면 수동 지정 사유를 기록해야 한다.
9-9. 직접 지정 요청 SMS 발송에 성공하면 설치 예약은 `WAITING_INSTALLER_RESPONSE` 상태로 전환하고 활성 배정 시도 유형은 `MANUAL_DIRECT`, 상태는 `WAITING_INSTALLER_RESPONSE`가 된다.
9-10. 직접 지정 요청 SMS 발송이 일시 실패하면 설치 예약의 현재 상태를 유지하고 같은 배정 시도 상태를 `SYSTEM_SMS_RETRY_PENDING`으로 기록한다.
9-11. 직접 지정 요청 SMS 발송 실패가 복구되지 않으면 활성 배정 시도를 `SYSTEM_SMS_FAILED`로 종료하고 SMS 실패 예외를 만든다.
9-12. 직접 지정 요청이 거절 또는 timeout으로 종료되면 설치 예약을 수동 처리 필요로 표시하고 차순위 자동 요청은 진행하지 않는다.
9-13. 관리자는 후보 선정 재실행을 요청할 수 있다.
9-14. 재실행 결과 후보가 있으면 시스템은 활성 배정 시도 유형을 `ADMIN_RETRY`, 상태를 `WAITING_ADMIN_REVIEW`로 기록하고 설치 예약을 `WAITING_ADMIN_REVIEW` 상태로 전환한다.
9-15. 재실행 결과 후보가 없으면 설치 예약의 현재 상태를 유지하고 후보 없음 예외를 만든다.
9-16. 재실행 후 배정 요청 SMS 발송이 일시 실패하면 설치 예약의 현재 상태를 유지하고 같은 배정 시도 상태를 `SYSTEM_SMS_RETRY_PENDING`으로 기록한다.
9-17. 재실행 후 배정 요청 SMS 발송 실패가 복구되지 않으면 활성 배정 시도를 `SYSTEM_SMS_FAILED`로 종료하고 SMS 실패 예외를 만든다.
9-18. 재실행 요청이 거절 또는 timeout으로 종료되면 설치 예약을 수동 처리 필요로 표시하고 차순위 자동 요청은 진행하지 않는다.
9-19. 관리자는 설치건을 취소할 수 있다.
9-20. 관리자는 현재 상태와 관계없이 설치 완료 처리할 수 있다.

## 10. 취소와 완료 플로우

10-1. 관리자는 `COMPLETED` 또는 `CANCELLED`가 아닌 설치건을 취소할 수 있다.
10-2. 시스템은 취소 사유, 관리자, 시각을 감사 이력으로 기록한다.
10-3. 취소 후 설치 예약은 `CANCELLED` 상태가 된다.
10-4. `CANCELLED` 상태에서는 고객 리마인드, 후보 선정, 기사 timeout, 차순위 진행을 실행하지 않는다.
10-5. 설치건 취소 시 시스템은 고객과 설치 기사에게 자동 SMS를 발송하지 않는다.
10-6. `INSTALLER_ASSIGNED` 상태에서 설치건을 취소해도 이미 확정된 배정 카운트는 유지한다.
10-7. 관리자는 슈퍼 권한으로 현재 상태와 관계없이 모든 설치건을 설치 완료 처리할 수 있다.
10-8. 설치 완료 처리 시 활성 배정 시도가 있으면 시스템은 해당 배정 시도를 `ADMIN_COMPLETED`로 종료한다.
10-9. 시스템은 완료 처리 관리자 ID, 완료 시각, 완료 사유를 감사 이력으로 기록한다.
10-10. 설치 완료 후 설치 예약은 `COMPLETED` 상태가 된다.

## 11. 예외 및 알림 플로우

11-1. 설치 희망 날짜 하루 전 09:00 KST까지 설치 예약이 `INSTALLER_ASSIGNED`, `COMPLETED`, `CANCELLED` 상태가 아니면 시스템은 일정 임박 예외를 만든다.
11-2. 일정 임박 예외가 열린 설치 예약이 `INSTALLER_ASSIGNED`, `COMPLETED`, `CANCELLED` 상태가 되면 시스템은 해당 예외를 해결 처리한다.
11-3. 모든 필수 SMS 발송 실패는 최초 발송과 자동 재시도 1회를 합쳐 최대 2회까지 같은 업무 대상 기준으로 재시도한다.
11-4. 모든 필수 SMS 도달 실패는 최초 발송 포함 최대 2회까지 같은 업무 대상 기준으로 재시도한다.
11-5. 필수 SMS 실패가 재시도 후에도 복구되지 않으면 시스템은 SMS 실패 예외를 만든다.
11-6. 배정 요청 SMS 최종 실패는 상태 전이를 막거나 활성 배정 시도를 `SYSTEM_SMS_FAILED`로 종료한다.
11-7. 비배정 SMS 최종 실패는 업무 상태를 되돌리지 않고 SMS 실패 예외를 만든다.
11-8. 고객 배정 완료 SMS가 실패해도 설치 예약은 `INSTALLER_ASSIGNED` 상태를 유지한다.
11-9. 설치 기사 해피콜 안내 SMS가 실패해도 설치 예약은 `INSTALLER_ASSIGNED` 상태를 유지한다.
11-10. 모든 외부 API 결과 확인 실패는 최대 2회까지만 자동 확인하고, 이후 열린 예외로 관리자에게 표시한다.
11-11. 미완료 설치건은 자동 처리 진행, 재시도 예약, 열린 예외 중 하나를 반드시 가져야 하며 어느 조건에도 해당하지 않으면 `INSTALLATION_WORKFLOW_ORPHANED` 예외를 만든다.
11-12. 제공사가 SMS 도달 성공을 반환하면 알림을 `DELIVERED`로 전환하고 이후 도달 결과 조회에서 제외한다.
11-13. 도달 결과 확인 재시도 횟수는 연속 미확인 또는 조회 API 실패에만 증가하며, 정상 결과 또는 새 SMS 발송 시 0으로 초기화한다.

## 13. 감사 이력

13-1. 시스템은 상태 변경을 모두 감사 이력으로 기록한다.
13-2. 시스템은 후보 선정 실행, 요청 발송, 기사 수락, 기사 거절, timeout, 관리자 직접 지정, 관리자 수동 처리 전환, 재시도, 취소, 완료를 기록한다.
13-3. 시스템은 고객 입력 검증 실패, SMS 일시 실패, SMS 실패 예외 생성, 일정 임박 예외 생성과 해결을 기록한다.
13-4. 시스템은 활성 배정 시도 유형, 활성 배정 시도 상태, SMS 재시도 대기 여부 변경을 감사 이력 또는 배정 시도 이력으로 기록한다.
13-5. 관리자 설치건 상세는 감사 이력을 시간순으로 표시한다.
